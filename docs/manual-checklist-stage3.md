# 第3段階 ユーザー確認手順

## 1. この確認の目的

ロード画面の操作が、ソフトウェア開発に詳しくない利用者でも理解できるか確認する。

プログラムの仕組みやJSONの仕様を完全に理解する必要はない。「迷った」「意味が分からなかった」という感想も重要な確認結果である。

## 2. 確認前の注意

- この確認では、ピアノや実鍵盤は使用しない。
- Canvasや音符の流れる画面はまだ実装されていない。
- 誤操作してもプロジェクトのコードは壊れない。
- JSON欄を変更しても、明示的にファイルへ書き出さない限り永続保存されない。
- 読み込んだファイルは外部へ送信されない。

## 3. 確認する画面

設計スレッドが起動した次の画面を使用する。

```text
http://127.0.0.1:5173/app/
```

画面を開けない場合は、無理に設定を変更せず、表示されたエラーを設計スレッドへ伝える。

## 4. 確認手順

### 手順1: 最初の画面

画面を開き、次が見えることを確認する。

- `piano-roll-score` という見出し
- 「内蔵サンプル」
- 「JSONファイル読み込み」
- 「楽曲JSON編集」
- 「確認結果」

確認すること:

- 文字が小さすぎないか
- どこから操作を始めるか想像できるか
- 横方向にはみ出していないか
- 難しすぎる説明文がないか

### 手順2: 内蔵サンプルを読み込む

「ドからソまで」の横にある「JSON欄に読み込む」を押す。

正常な状態:

- JSON欄へ長いテキストが表示される
- 確認結果に「JSONは有効です。」と表示される
- 曲名、説明、BPM、拍子、音部記号、音符数、表示音域が表示される
- ブラウザのURLの末尾に `?id=001` が付く

確認すること:

- どの曲を読み込んだか分かるか
- 成功したことが分かりやすいか
- JSON欄の存在が邪魔に感じないか

### 手順3: JSONを編集する

JSON欄の中から次の行を探す。

```json
"bpm": 80
```

`80` を `90` に変更し、「JSONを確認」を押す。

正常な状態:

- 「JSONは有効です。」と表示される
- BPMが `90` と表示される
- URLから `?id=001` が消える

次に、`90` を `10` に変更し、もう一度「JSONを確認」を押す。

正常な状態:

- 赤色のエラーが表示される
- `bpm` という場所が示される
- BPMは20以上という原因が示される

最後に `10` を `80` に戻して、「JSONを確認」を押す。

正常な状態:

- 再び「JSONは有効です。」と表示される

確認すること:

- 編集後に何を押せばよいか分かるか
- エラーの場所と修正方法を理解できそうか
- エラー後にやり直しやすいか

### 手順4: 破棄確認

JSON欄の曲名を少し変更する。

例:

```json
"title": "ドからソまで テスト"
```

変更後、「ド♯とレ♭」の「JSON欄に読み込む」を押す。

確認ダイアログが表示されたら、最初は「キャンセル」を選ぶ。

正常な状態:

- 編集した「ドからソまで テスト」が残っている

もう一度「ド♯とレ♭」の「JSON欄に読み込む」を押し、今度は破棄を許可する。

正常な状態:

- JSON欄が「ド♯とレ♭」の内容へ置き換わる
- 確認結果も「ド♯とレ♭」になる

確認すること:

- 確認ダイアログの意味が分かるか
- 間違って編集内容を失いにくいと感じるか

### 手順5: JSONを書き出す

「JSONを書き出す」を押す。

正常な状態:

- `002.json` がダウンロードされる
- ブラウザによっては画面上部または右上にダウンロード通知が出る

ダウンロードされない場合は、ブラウザがダウンロードを許可するか尋ねていないか確認する。判断できない場合は、その画面の内容を設計スレッドへ伝える。

### 手順6: 書き出したJSONを読み込む

「JSONファイルを選択」を押し、手順5でダウンロードした `002.json` を選ぶ。

正常な状態:

- JSON欄へ「ド♯とレ♭」の内容が表示される
- 「JSONは有効です。」と表示される
- URLの `?id=002` は消えてよい

確認すること:

- ファイル選択の場所が分かりやすいか
- 読み込み成功を判断できるか

## 5. 確認結果の伝え方

次の形式で設計スレッドへ伝える。

```text
1. 最初の画面: 問題なし / 問題あり
2. サンプル読み込み: 問題なし / 問題あり
3. JSON編集とエラー: 問題なし / 問題あり
4. 破棄確認: 問題なし / 問題あり
5. JSON書き出し: 問題なし / 問題あり
6. JSON再読み込み: 問題なし / 問題あり

分かりにくかったところ:

改善してほしいところ:
```

「問題あり」の場合は、次も分かる範囲で伝える。

- どの手順で起きたか
- 押したボタン
- 画面に表示された文
- 期待していた結果
- 実際に起きた結果

画面のスクリーンショットを添付してもよい。
