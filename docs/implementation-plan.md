## 5. 第2段階の設計決定

### 5.1 実行時検証

- Zodを導入する。
- TypeScript型は、可能な限りZodスキーマから推論する。
- 同じ構造を手書き型とスキーマへ重複定義しない。
- JSON、`fetch` の結果、URLパラメーターは信頼できない入力として扱う。

### 5.2 音高

- `pitch` はMIDIノート番号とする。
- 中央のドは `60` とする。
- MVPで受け付ける範囲は88鍵ピアノの `21` から `108` とする。
- `spelling` は `step`、`accidental`、`octave` を持つ。
- `accidental` は `natural`、`sharp`、`flat` とする。
- MIDI番号は `C-1 = 0` の規則で計算する。
- `pitch` と `spelling` が同じ実音高を示すことを検証する。
- ド♯4とレ♭4は、どちらもMIDI番号 `61` として有効である。

### 5.3 楽曲データ

基本構造は `spec.md` のJSON例に従う。

追加で次を明確にする。

- `schemaVersion` は `1` のみ対応する。
- 曲の `id` は省略可能とする。
- 内蔵曲の `id` は英数字、ハイフン、アンダースコアだけを許可する。
- `title` は空文字を許可しない。
- `bpm` は20以上300以下とする。
- `timeSignature.numerator` は1以上32以下の整数とする。
- `timeSignature.denominator` は `1`、`2`、`4`、`8`、`16`、`32` のいずれかとする。
- `notes` は1件以上、5,000件以下とする。
- 音符IDは曲内で一意とする。
- `time` は0以上とする。
- `duration` は0より大きい値とする。
- `finger` は1から5とする。
- `hand` の省略時は `unspecified` として扱う。
- `displayRange` は次のどちらかとする。

```json
{ "mode": "auto" }
```

```json
{
  "mode": "fixed",
  "minPitch": 60,
  "maxPitch": 69
}
```

- 固定範囲では `minPitch <= maxPitch` とする。
- 固定範囲では、すべての音符が範囲内にあることを検証する。
- 同時刻の複数音符は有効とする。

### 5.4 内蔵曲一覧

`public/data/songs/index.json` は次の形式を基準とする。

```json
{
  "schemaVersion": 1,
  "songs": [
    {
      "id": "001",
      "title": "ドからソまで",
      "description": "右手の導入確認",
      "level": "導入"
    }
  ]
}
```

- 実ファイルは `public/data/songs/{id}.json` とする。
- ファイルパスを一覧JSONから自由指定させず、検証済みIDから組み立てる。
- 内蔵曲JSONでは `id` を必須とし、要求されたIDと一致することをデータ取得層で検証する。
- 一覧内のID重複を許可しない。
- `/app/` 以外のサブパスへ将来変更しても動くよう、`import.meta.env.BASE_URL` を基準にURLを作る。

### 5.5 内蔵サンプル

少なくとも次の2件を用意する。

1. `001`: 自然音を使った短い右手導入課題
2. `002`: ド♯4とレ♭4が同じ鍵盤位置を示す検証用課題

この段階のサンプルは、データ形式と読み込みの検証を主目的とする。教育教材としての最終内容は、Canvas表示を確認できる段階で調整してよい。

## 6. 第2段階の補正作業

第3段階の機能には着手せず、次だけを修正する。

### 6.1 内蔵曲IDの整合性

- `loadBuiltinSong(baseUrl, id)` で取得した内蔵曲について、データ内の `id` が存在することを確認する。
- データ内の `id` が要求された `id` と一致することを確認する。
- `id` がない場合と一致しない場合は、`validation` 種別の回復可能なエラーにする。
- エラーには利用者向けの日本語メッセージと、開発者が原因を特定できる検証情報を含める。

### 6.2 BPMと拍子

- BPMを20以上300以下へ制限する。
- 拍子の分子を1以上32以下へ制限する。
- 拍子の分母を `1`、`2`、`4`、`8`、`16`、`32` のいずれかへ制限する。
- 境界値を含む単体テストを追加する。

### 6.3 テスト

少なくとも次を追加または更新する。

- BPM 20と300を許可する
- BPM 20未満と300超を拒否する
- 拍子の分子1と32を許可する
- 拍子の分子0と33を拒否する
- 許可した拍子の分母を受け付ける
- 分母3など未対応値を拒否する
- 内蔵曲データの `id` 欠落を拒否する
- 要求IDとデータ内IDの不一致を拒否する
- 正常な `001` と `002` の読み込みを維持する

### 6.4 第2段階の確定

補正後に全検証を実行する。
