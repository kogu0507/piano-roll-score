## 6. 鍵盤幾何モデル

### 6.1 基本

- MIDI 21から108の88鍵範囲を扱う。
- 白鍵を連続する基準単位として扱う。
- 白鍵の左端と右端をレーン境界とする。
- 黒鍵の中心は、該当する前後の白鍵の境界に置く。
- 黒鍵幅は白鍵幅の `0.62` とする。
- B-C間とE-F間に黒鍵を作らない。

実際のピアノ製品ごとの数ミリ単位の黒鍵位置差まではMVPで扱わない。白鍵境界を基準とするモデルで教育実験を行い、必要性が確認された場合に補正テーブルを検討する。

### 6.2 表示音域

`displayRange.mode` が `fixed` の場合:

- `minPitch` と `maxPitch` を使用する。

`displayRange.mode` が `auto` の場合:

- 音符の最小MIDI番号と最大MIDI番号を使用する。

どちらの場合も、最終的な描画境界は白鍵の外周へ正規化する。

- 端が白鍵の場合は、その白鍵全体を含める。
- 端が黒鍵の場合は、その黒鍵を挟む前後の白鍵を含める。
- 追加の白鍵余白を自動では付けない。

例:

- C4からG4は、C・D・E・F・Gの5白鍵分
- C4からD4は、C・Dの2白鍵分
- C♯4だけの場合は、C・Dの2白鍵分

### 6.3 座標

幾何計算はDOMとCanvasから分離したピュア関数として実装する。

最低限、次を計算できるようにする。

- MIDI番号が白鍵か黒鍵か
- MIDI番号に対応する白鍵通し番号
- 表示音域に含まれる白鍵
- 各白鍵の矩形
- 各黒鍵の矩形
- 各音符ブロックの横位置と幅
- 対象音域の全幅

音符ブロック:

- 白鍵音は、対応する白鍵レーン内へ少量の左右余白を付ける。
- 黒鍵音は、黒鍵幅を基準にする。
- 同じ `pitch` は同じ横位置にする。
- `spelling` は横位置には影響させない。

## 7. 縦方向と静止プレビュー

### 7.1 判定ラインと鍵盤ガイド

- Canvas下部に簡易鍵盤ガイドを描画する。
- 白鍵ガイドの高さは72 CSS pxを基準とする。
- 黒鍵ガイドの高さは42 CSS pxを基準とする。
- 判定ラインは白鍵ガイドの上端とする。
- 判定ラインより上を音符表示領域とする。

### 7.2 時間座標

- 静止プレビューの現在位置は0拍とする。
- 1拍は64 CSS pxとする。
- 音符の開始時刻が判定ラインへ到達する位置を基準にする。
- `duration` は判定ラインから上方向へ伸びるブロック長へ変換する。

計算の基準:

```text
noteBottomY = judgmentLineY - time * pixelsPerBeat
noteHeight = duration * pixelsPerBeat
noteTopY = noteBottomY - noteHeight
```

Canvas外のブロックはクリップまたは描画省略してよい。

### 7.3 表示内容

- 音符ブロックへ日本語音名を表示する。
- ド♯とレ♭を区別する。
- オクターブ番号は通常表示しない。
- 指番号が存在する場合は音名と区別して表示する。
- 右手、左手、指定なしに一貫した色を割り当てる。
- 色だけに依存しないよう、画面上に短い凡例または識別情報を置く。

## 8. 鍵盤位置調整

### 8.1 白鍵幅

- 16から320 CSS px
- 1 CSS px単位
- `<input type="range">` を使用する
- 現在値を数値でも表示する
- 変更を即時描画へ反映する

幅変更時は、対象音域の中心が画面上で大きく移動しないよう横位置を補正する。

### 8.2 画面幅に合わせる

「画面幅に合わせる」ボタンを用意する。

- `Canvas表示幅 ÷ 対象白鍵数` で白鍵幅を計算する。
- 16から320 CSS pxへ正規化する。
- 対象音域を中央へ置く。
- 課題音域に対する不要な余白を最小にする。

初回表示でもこの計算を使用する。

### 8.3 横位置

- 横位置調整用のrange入力を用意する。
- 1 CSS px単位で移動できる。
- 対象音域全体をCanvasの左右へ移動できる範囲を持たせる。
- 現在値を表示する。
- 「中央に戻す」ボタンを用意する。

Canvas上での横方向ドラッグにも対応する。

- ドラッグ量を横位置へ反映する。
- range入力と同期する。
- 縦スクロールを必要以上に妨げないよう、横方向の意図が確認できた場合にドラッグとして扱う。
- Pointer Eventsを優先する。

### 8.4 Canvasからのクリップ

- 対象音域がCanvasより広い場合はCanvas内でクリップする。
- ページ全体に横スクロールを発生させない。
- Canvasの描画領域外へDOM要素を広げない。

この段階では調整値を永続保存しない。保存は第8段階で実装する。

## 9. Canvas実装

### 9.1 高DPI

- CSS上の表示サイズとCanvasの内部ピクセルサイズを分ける。
- `devicePixelRatio` を考慮する。
- 描画関数はCSS px基準の座標を使用する。
- DPRを変更または端末を移動した場合にも再描画できる構造にする。

### 9.2 サイズ変更

- `ResizeObserver` または同等の方法でCanvasコンテナを監視する。
- ウィンドウサイズ変更と端末回転時に再計算・再描画する。
- 初回表示、曲変更、幅変更、横位置変更でも再描画する。

### 9.3 責務分離

次を分離する。

- 鍵盤幾何計算
- 音符矩形とラベルを含む描画シーン計算
- Canvas 2D APIによる実描画
- 縦表示画面のDOMとイベント

Canvas描画をテストするため、可能な限り「何をどこへ描くか」をシーンデータとしてピュアに計算し、Canvas API層を薄くする。

## 12. E2Eテスト

PC幅とスマートフォン幅で少なくとも次を確認する。

- 有効な楽曲で「縦表示を確認」を押せる
- 編集中または不正なJSONでは縦表示へ進めない
- 縦表示画面にCanvasと曲名が表示される
- 「静止プレビュー」と明示される
- 白鍵幅スライダーを変更できる
- 横位置スライダーを変更できる
- 「画面幅に合わせる」が動作する
- 「中央に戻す」が動作する
- Canvasを横方向へドラッグすると横位置が変わる
- ロード画面へ戻るとJSONと検証結果が保持される
- 画面サイズ変更後にCanvas内部サイズが更新される
- Canvas内部サイズがCSSサイズとDPRに対応する
- ページ全体の横スクロールが発生しない

Canvasの厳密なピクセル一致を主要判定にしない。座標とシーンデータは単体テストし、E2Eでは画面遷移、調整操作、サイズ更新を確認する。
