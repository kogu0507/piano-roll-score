## 4. 第7段階の目的

第7段階の目的は、視覚的な再生に拍の音を加え、利用者が入るタイミングを取りやすくすることである。

具体的には次を実現する。

- メトロノームON/OFFを切り替えられる。
- 1拍目は高い音、その他の拍は低い音にする。
- メトロノーム音量を調整できる。
- 再生速度変更にメトロノーム音も追従する。
- プリカウントを「なし」「1小節」「2小節」から選べる。
- プリカウント中は譜面を進めず、カウント後に既存の再生を開始する。
- 縦表示と横表示のどちらでも同じメトロノーム・プリカウント設定を使う。

## 5. Web Audio APIの扱い

### 5.1 初期化

- AudioContextは、利用者の操作後に初期化または `resume()` する。
- ページ表示時に自動で音を鳴らそうとしない。
- ブラウザの自動再生制限によりAudioContextが `suspended` になる場合を想定する。
- 音を開始できない場合は、画面が壊れないようにし、可能なら「もう一度スタートを押してください」程度の回復可能な案内にする。

### 5.2 音の作り方

- 外部音源ファイルは使わず、Web Audio APIの `OscillatorNode` と `GainNode` などで短いクリック音を生成する。
- 1拍目は高い音、その他の拍は低い音にする。
- 音は短く、長く残らないようにする。
- 音量は0から100%相当の範囲で調整できるようにする。
- 音量の初期値は大きすぎない値にする。推奨は50%から60%程度である。

### 5.3 スケジューリング

- メトロノームは `requestAnimationFrame` だけに依存しない。
- Web Audio APIの時刻を使い、可能な範囲で少し先の拍をスケジュールする。
- 先読み幅、タイマー間隔などの実装値は、テストしやすい小さな関数として分離する。
- 再生、一時停止、先頭に戻す、シーク、再生速度変更、タブ非表示に追従して、不要な予約音が鳴り続けないようにする。

## 6. プリカウント仕様

### 6.1 選択肢

プリカウントは次の3択とする。

- なし
- 1小節
- 2小節

この段階では設定を永続保存しない。永続保存は第8段階で扱う。

### 6.2 小節数と拍数

- 1小節あたりの拍数は、楽曲データの `timeSignature.numerator` を基準にする。
- 現在のデータ形式では音符の `time` と `duration` は拍単位で扱っているため、4/4なら1小節は4拍、3/4なら1小節は3拍として扱う。
- `timeSignature.denominator` は表示上の拍子情報として保持するが、第7段階のプリカウント長計算では `numerator` を基準にする。

### 6.3 開始時の挙動

- 停止中または終了後に「スタート」を押したとき、プリカウントが「1小節」または「2小節」なら、まずプリカウント状態へ入る。
- プリカウント中は `currentBeat` を進めない。
- プリカウントが終わったら、プリカウント開始前の `currentBeat` から再生を開始する。
- 一時停止からの再開では、原則としてプリカウントを挟まず、その位置から再開する。停止中から始めるときだけプリカウントを使う。
- 「先頭に戻す」を押した後は停止状態なので、次のスタートではプリカウント対象になる。

### 6.4 プリカウント中のUI

- 状態表示に「プリカウント中」と分かる表示を出す。
- 可能であれば、現在のカウント拍を表示する。
- プリカウント中に一時停止または先頭に戻す操作をした場合は、プリカウントをキャンセルする。
- プリカウント中に縦横表示を切り替えても、アプリが壊れないようにする。可能な範囲でプリカウント状態を維持するが、実装上難しい場合は安全に停止してよい。その場合は完了報告に判断を記載する。

- メトロノームON/OFF

- プリカウント

スマートフォンでも押しにくくならないよう、既存の再生操作欄を詰め込みすぎない。必要に応じて折り返しやグルーピングで整理する。

## 8. 既存機能との関係

維持すること:

- 縦表示と横表示の共通 `currentBeat`
- スタート、一時停止、先頭に戻す、シーク、再生速度変更
- 縦表示で音符が上から下へ流れること
- 横表示で音符が右から左へ流れること
- 縦横切り替え時の現在位置維持
- タブ非表示時の自動一時停止
- 縦表示の白鍵幅調整と横位置調整
- 横表示の五線間隔調整と譜面縦位置調整
- ロード画面へ戻ったときのJSONと検証結果保持
- C♯とD♭の扱い
- 高DPI Canvas、リサイズ、端末回転対応
- ページ全体に横スクロールを発生させないこと

壊してはいけない分離:

- シークは曲の現在位置を変える操作である。
- 縦表示の白鍵幅・横位置調整は表示調整である。
- 横表示の五線間隔・譜面縦位置調整は表示調整である。
- メトロノームとプリカウントは再生補助であり、音符のピアノ音源再生ではない。

## 12. E2Eテスト

PC幅とスマートフォン幅で少なくとも次を確認する。

- メトロノームON/OFFを切り替えられる。
- メトロノーム音量を変更できる。
- プリカウントを「なし」「1小節」「2小節」から選べる。
- プリカウントありでスタートすると、まず「プリカウント中」などの状態になる。
- プリカウント中は現在位置が進まない。
- プリカウント後に再生が始まり、現在位置が進む。
- 一時停止からの再開が壊れない。
- 再生速度変更後も再生操作が壊れない。
- 縦表示と横表示を切り替えても操作欄が使える。
- スマートフォン幅でも主要操作ができる。
- ページ全体の横スクロールが発生しない。

E2Eでは実際の音声出力を厳密に判定しない。ブラウザやOSの音量、権限、再生制限の影響があるため、UI状態と再生状態を中心に確認する。

## 19. 第7.5段階 再生ガイドと助走表示

### 19.1 目的

第7.5段階の目的は、アプリの見え方を音楽ゲーム的な「判定線へ完全一致させる」ものから、教育用の「テンポと譜面の流れをつかむ」ものへ寄せることである。

ユーザー手動確認では、PCで再生速度変更時に画面とメトロノームの同期が少しずれることがあり、赤い線があるためにそのズレが強く気になると報告された。MVPでは演奏判定を行わないため、赤い判定線を強く見せる必要はない。

### 19.2 実装方針

- 「判定ライン」というUI文言を「再生ガイド」へ変更する。
- 赤い強い線ではなく、薄い線または半透明の帯として表示する。
- 縦表示と横表示の両方で同じ方針にする。
- プリカウント中も、表示用の助走位置で譜面を流す。
- 実際の `currentBeat` はプリカウント中に進めない。
- Canvas描画には、実再生位置とは別の `displayBeat`、`renderBeat`、または同等の表示用拍位置を渡せるようにする。
- プリカウント終了後は、表示用拍位置と実際の `currentBeat` が自然につながるようにする。
- シーク、現在位置表示、保存対象の再生位置は、実際の `currentBeat` を基準にする。

### 19.3 助走表示の考え方

プリカウント中の表示用拍位置は、次のような考え方を基準とする。

```text
displayBeat = currentBeat - precountRemainingBeats
```

たとえば、4/4で1小節プリカウントの場合は、開始時に `displayBeat = -4` として描画し、カウントが進むにつれて `displayBeat` が0へ近づく。これにより、1拍目から突然画面が動き出すのではなく、テンポに合わせて譜面が先に流れ始める。

実装上より自然な計算があれば調整してよい。ただし、プリカウント中に利用者へ表示する「曲の現在位置」は、0拍または開始前であることが分かる表示にする。

### 19.4 実装しないもの

- 音符に対応するピアノ音源再生
- 演奏判定
- マイク入力
- MIDI入力
- 設定の永続保存
- 端末内への楽曲保存
- 本格的な楽譜組版
- アウフタクトのデータ形式変更

アウフタクト対応に役立つ設計ではあるが、この段階ではデータスキーマや既存曲データを変更しない。

### 19.5 テスト

少なくとも次を確認する。

- プリカウント中の表示用拍位置が、負の値または開始前の値として進む。
- プリカウント中も実際の `currentBeat` は進まない。
- プリカウント終了後に、表示用拍位置と `currentBeat` が自然につながる。
- 縦表示で、プリカウント中に音符ブロックが流れる。
- 横表示で、プリカウント中に音符ブロックが流れる。
- 再生ガイドが赤い判定線として強く見えすぎない。
- UI文言に「判定ライン」が残らず、「再生ガイド」へ置き換わっている。
- 既存のメトロノームON/OFF、音量、プリカウント、再生速度、シークを壊さない。
- スマートフォン幅で横スクロールが発生しない。
